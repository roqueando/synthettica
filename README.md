# Synthettica

A tiny **3-voice synthesizer + 808-style kick drum machine** running on an
RP2040 (Raspberry Pi Pico / Waveshare RP2040-Zero), written in C with the
Pico SDK.

It generates three continuously-running oscillators — **sine, square and
saw** — each with its own frequency knob, mixes them into a single PWM audio
output, and layers an analog-style kick drum that fires on every beat of a
tempo clock. A 128×64 OLED shows the live frequencies, tempo, kick state and
the mixed waveform. No PC, MIDI or audio interface is required: the whole
instrument is self-contained.

```
                 ┌──────────────────────────────────────────────┐
  SIN  freq ───► │                                              │
  SQR  freq ───► │  RP2040  3-voice mix  ──► PWM (GP7) ──► RC ──►  out
  SAW  freq ───► │                                              │
  BPM      ───► │  + 808 kick (per beat, toggle via button)      │
  button   ───► │                                              │
                 │  OLED (I2C): freqs · BPM · kick · waveform   │
                 └──────────────────────────────────────────────┘
```

## Features

- **3 voices** — sine, square and saw, each with an independent frequency
  knob (80 Hz – 1 kHz).
- **808-style kick drum** — exponential pitch sweep (180 → 45 Hz) and
  amplitude decay, triggered on every beat.
- **Tempo control** — a 4th knob sets the beat rate (10 – 120 BPM).
- **Kick on/off** — a momentary push button toggles the kick drum.
- **OLED display** — 128×64 SSD1306/SH1106 screen showing each voice's
  frequency, the BPM, kick state, a beat indicator and the mixed waveform.
- **Serial monitor** — USB CDC log of all parameters at 5 Hz.
- **Pure integer/table-based audio path** — no `sinf()` or float division in
  the audio callback; samples are generated by a phase-accumulator + wavetable
  design.

## What you hear

The three oscillators are summed and normalized, then centered on the PWM
midpoint:

```c
out = 0.5 * (sine + square + saw) / 3  +  0.8 * kick;
```

`out` is written to an **8-bit PWM** (wrap = 255) running at a ~488 kHz
carrier, so the duty cycle represents the instantaneous sample value. A
single-pole RC low-pass on the output pin removes most of the carrier and
leaves the audio. The output is unipolar (biased around 1.65 V) and is meant
for a scope or a high-impedance amplifier input — see
[Audio output](#audio-output).

| 10 µF capacitor (optional) | 1 | AC-couples the output into an amplifier |
| Breadboard + jumper wires | — | |

> **Board choice:** the BPM knob is read on **GP29 = ADC3**. The standard
> Raspberry Pi Pico does **not** break GP29 out to a pin (it is wired to the
> on-board VSYS monitor divider). The Waveshare RP2040-Zero exposes GP29, so it
> is the recommended board. On a plain Pico, either skip the BPM knob, remap
> `BPM_ADC_GPIO` to a free ADC pin, or leave GP29 floating (the reading will be
> meaningless but harmless).

### Audio output

The PWM pin (GP7) carries a ~488 kHz carrier whose duty cycle is the sample
value. A single-pole RC low-pass removes the carrier:

```text
GP7 ─── 1 kΩ ───●─── filtered output (scope probe tip / amp input)
                │
              100 nF
                │
GND ────────────●─── scope ground clip
```

Nominal cutoff: `1/(2π·R·C) ≈ 1.59 kHz`. Use a non-polar ceramic capacitor.

- Do **not** connect the scope ground clip to GP7.
- Do **not** drive headphones or a speaker directly from the pin — the signal
  is biased around 1.65 V and is unamplified. Use an audio amplifier, and
  **AC-couple** the input with a series capacitor (e.g. 10 µF).

## Build

### Prerequisites

- CMake ≥ 3.13 and Ninja
- Arm GNU embedded toolchain (`arm-none-eabi-gcc`)
- [Raspberry Pi Pico SDK](https://github.com/raspberrypi/pico-sdk) (with its
  submodules)

See Raspberry Pi's
[C/C++ SDK getting started guide](https://www.raspberrypi.com/documentation/microcontrollers/c_sdk.html)
for the full setup.

Clone the SDK once and initialize its submodules:

```sh
git clone https://github.com/raspberrypi/pico-sdk.git
cd pico-sdk
git submodule update --init
```

### Compile

From this project's root (point `PICO_SDK_PATH` at your SDK clone):

```sh
cmake -S . -B build -G Ninja \
  -DPICO_SDK_PATH=/absolute/path/to/pico-sdk \
  -DPICO_BOARD=pico
cmake --build build
```

This produces `build/sine_pwm.uf2` (the executable is still named `sine_pwm`
from the original starter). For a Pico W, pass `-DPICO_BOARD=pico_w` instead.

## Flash

Pick one of the two methods below.

### Method 1 — BOOTSEL drag-and-drop

1. Disconnect the board from USB.
2. Hold the **BOOTSEL** button while reconnecting USB, then release it. The
   board mounts as a USB drive named `RPI-RP2`.
3. Copy `build/sine_pwm.uf2` onto that drive. The board reboots automatically
   and starts running.

### Method 2 — picotool

If [picotool](https://github.com/raspberrypi/picotool) is installed:

```sh
# put an already-running board into BOOTSEL mode, or hold BOOTSEL while
# connecting, then:
picotool load build/sine_pwm.uf2
picotool reboot
```

## Usage

1. Power the board over USB. The OLED should light up and show the three
   frequencies, the BPM, and a scrolling mixed waveform.
2. Turn the **SIN / SQR / SAW** knobs to set each oscillator's pitch
   (80 Hz – 1 kHz). The display updates at ~10 Hz.
3. Turn the **BPM** knob to set the beat rate (10 – 120 BPM).
4. Press the **button** to toggle the kick drum on/off. When on, a kick fires
   on every beat and the top-right square flashes in time.
5. Listen on the filtered output, or probe GP7 with a scope (DC coupling,
   ~1 V/div, 500 µs/div to see a few cycles; the period of a 440 Hz tone is
   ~2.27 ms).

### Serial monitor

The firmware logs all parameters at 5 Hz over USB CDC:

```
SIN= 440 SQR= 440 SAW= 440 BPM=120 KICK=OFF
```

Open the board's USB serial port with any terminal (e.g. `screen`,
`minicom`, or the Arduino Serial Monitor). USB CDC needs no baud rate.

## How it works

The firmware is split into a **hard-real-time audio path** and a **slow
control path** that never block each other.

### Audio callback (23 µs repeating timer)

A `repeating_timer` fires every 23 µs (~43.5 kHz). On each tick it:

1. Generates one sample per voice from a 32-bit phase accumulator
   (`phase += phase_step`, where `phase_step = freq · 2³² / sample_rate`).
2. Reads the waveform value:
   - **sine** — 1024-entry precomputed wavetable (top 10 bits of the phase);
   - **square** — top bit of the phase;
   - **saw** — upper 16 bits of the phase scaled to −1…1.
3. Averages the three voices, adds the kick sample, and writes the result to
   the PWM duty register with `pwm_set_gpio_level()`.

The timer uses a **negative interval** (`-23 µs`), which schedules each
deadline from the previous one, so the sample clock does not drift.

### Kick drum

The kick is a classic 808-style voice: a sine whose frequency sweeps
exponentially from 180 Hz down to 45 Hz while its amplitude decays
exponentially, lasting 0.5 s. The sweep/decay coefficients are precomputed
once with `expf()`; the per-sample math is pure multiply. A beat clock (one
countdown per sample) triggers a new kick when `g_beat_countdown` reaches zero.

### Control loop (100 Hz)

The foreground `while` loop:

- reads each pot (8-sample average, first sample discarded for mux settling);
- low-pass-filters the target values (smoothing factor 0.15) to avoid zipper
  noise, then updates each voice's `phase_step` (a `volatile` value read by
  the callback);
- debounces the kick button (3 consecutive reads ≈ 30 ms);
- redraws the OLED at ~10 Hz and prints the serial log at ~5 Hz.

Communication between the loop and the callback is through small `volatile`
fields (phase step, samples-per-beat, kick enable, beat flash) — no locks, no
I²C/printing in the audio path.

## Troubleshooting

**No audio.** Check GP7 is set to `GPIO_FUNC_PWM`, the RC filter is wired
correctly, and the scope probe ground is on GND (not GP7).

**OLED stays blank.** Verify the I²C address (0x3C vs 0x3D) and set
`OLED_COL_OFFSET` to `2` if your panel is an SH1106. Check SDA/SCL aren't
swapped and that VCC matches the module's rating (most are 3.3 V).

**Kick never fires.** The button is active-low — it must connect GP4 to GND.
If the top-right beat square flashes but there's no thump, the kick is toggled
off; press the button once.

**BPM is stuck or jittery on a plain Pico.** GP29/ADC3 isn't broken out on the
stock Pico (it's the VSYS monitor). Use a Waveshare RP2040-Zero, or remap
`BPM_ADC_GPIO` to a free ADC pin.

**Pitch warbles / is noisy.** Pots read 0–4095 and are low-pass filtered, but
an unconnected ADC input will read random values. Make sure every pot's outer
legs are on 3V3 and GND and the wiper is on the ADC pin.

## Roadmap

- Precomputed wavetables for square/saw with a band-limited (anti-aliased)
  option.
- DMA-paced PWM output with a double buffer for rock-steady sample timing.
- Per-voice level/pan controls and a master volume.
- External I²S DAC for higher-fidelity output.
